# Hiku (the Safari extension): working notes

Container app target and scheme `Hiku` (folder `Hiku/`, bundle `com.amatsubame.hiku`) and the extension target `HikuExtension` (folder `HikuExtension/`, bundle `com.amatsubame.hiku.extension`); UI tests in `HikuUITests`. Read this when working on the extension. Shared notes are in [shared.md](shared.md).

- **Overview** (phase 9): the container app "Hiku" with the Safari Web Extension "Hiku".
  - Web files are in `HikuExtension/Resources`. "Japanese text only" (extension menu, on by default): the content script ignores a tap whose character isn't kana, kanji or full-width (`isJapaneseAt`), before asking the native side. Its UI test taps "OK", which Jitendex would match. The content script detects taps from pointer events (iOS Safari sends no page-wide click on plain text); with a popup open (and on screen), a tap on the page only closes it, links included (the click is swallowed), and otherwise drives the shared `TextTapBridge.js` (copied in at build, `lookupBridge.tapAt`, page mode when `window.lookupBridgePost` is set). The popup is an extension page in an iframe that fetches its HTML from the background page.
  - Native side: `Packages/Browser` (BrowserKit): `BrowserService` (lookup), `BrowserStorage`, the message protocol.
  - Dev builds can carry built-in dictionaries, **prebuilt on the Mac**: the build runs `scripts/prebuild-extension-dictionaries.sh` (the `dictionary-prebuild` tool in Packages/Dictionary). It reads `Dictionaries/Extension/*.zip` (gitignored; a folder or a link to wherever you keep your dictionary zips) or `Dictionaries/*.zip`, and caches the output in `Dictionaries/Prebuilt/*.hoshidict`.
    - **Why prebuilt:** importing a large dictionary (JPDB frequency) inside the extension needed more memory than iOS allows an extension on an iPad with less memory. SFErrorDomain error 3 means the extension process was stopped mid-message.
    - **On the device:** the extension only copies the prebuilt files (`DictionaryLibrary.installPrebuilt`), one dictionary at a time with saved progress. One that stops the process twice is skipped and named in the menu.
    - **Shared setup:** built-in dictionaries only fill an empty shared setup. The popup lists them bilingual first, then grammar, then the rest.
  - Popup actions go popup frame → background → native (`BrowserRequest`): audio, mine (queued with the apps' 5 s undo window, then `send` waits for that card's state), undo, glossary queries, and `saveAnki` from the extension's menu (only without the App Group; with it, AnkiConnect is set in the Hiku app).
  - Live mining check: `REAL_ANKI_URL=… REAL_ANKI_KEY=… REAL_ANKI_DECK=<scratch deck> swift test --filter BrowserLiveAnki` in `Packages/Browser` (create the deck first with `createDeck`; delete the note and deck afterwards).
  - UI test (`HikuUITests`): turns the extension on in the simulator's Settings, serves a page from the test, taps 食. `TEST_RUNNER_EXPECT_SHARED_DICTIONARY=<title>` checks the shared setup.
- **Word marks:** `marks.js` underlines words as Yomu's books do (not in the mining deck: Hiku's accent; learning: dotted grey; known: none), following the shared word marks setting. Paragraphs are sent to the native side as they come within 600 pt of the screen (`IntersectionObserver`, 20 per `marks` message; new content through a `MutationObserver`), split with the same `WordScanner`, and drawn as a short line per word (inset at both ends, so neighbours don't join, as in the apps) in a layer over the page (`position:absolute`, `z-index:0`, redrawn on resize), so the page's HTML is never changed. CSS highlights were tried first: their underlines ran together across neighbouring words. The extension asks Anki for mined words at most every 10 minutes. A word the lookup highlight wraps loses its mark until the page reloads.
- Hiku's accent is its icon's #EE4F6B (`AccentColor`, and `BrowserEnvironment.accent` for the popup).
