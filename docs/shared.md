# Shared setup, dictionaries, mining and downloads

Notes that apply to more than one app.

- **Data:** each app has its own container. The **shared setup** (App Group `group.com.amatsubame`, `Core/SharedSetup` + `SetupSharing`) holds dictionaries (one copy of the files), audio sources, AnkiConnect (account, settings, key in the shared Keychain group) and mined-word marks.
  - Each app's Settings has "Share Setup with My Other Apps" (on by default): a new app fills in from it, the first set-up app publishes its own, and an app with both asks. Turning it off copies the setup back; switching applies on the next launch.
  - Servers, progress, downloads, outbox and lookup history stay per app. Hiku and its extension share their own folder in the group, with the choice kept in the group's defaults (`setupSharing.lookup`).
  - On devices and the Mac the App Group needs a team in the paid Apple Developer Program (a free personal team can't sign it). Simulator builds always have it (`Shared/SharedSetup.entitlements`); elsewhere it's on when `Config/Signing.local.xcconfig` sets `AMATSUBAME_APP_GROUP = YES` (device: `Shared/SharedSetup.entitlements`; Mac: the `-AppGroup` variants of `Shared/App-macOS.entitlements` and `HikuExtension/HikuExtension-macOS.entitlements`). Without it everything runs independently. `group.com.amatsubame` is registered to the project owner's team; another team needs its own group ID (`SharedSetup.groupIdentifier` and the entitlements). The Keychain items use the App Group as their access group, so no separate Keychain group is needed.

- **Setting up a simulator for hands-on testing** (`DevSetup`, AppCommon, Debug builds only): launch an app once with `xcrun simctl launch` and `SIMCTL_CHILD_DEV_SETUP=1` plus `DEV_…` values, and it signs in through the same models as Settings and logs each step to `Application Support/dev-setup.log`. The first app sets up what's shared: `DEV_ANKI_URL/KEY`, `DEV_ANKI_SETTINGS` (AnkiSettings JSON, e.g. a scratch deck and the tag `amatsubame-test`, so test cards are easy to find and delete), `DEV_AUDIO_SOURCES` (AudioSourceRecord JSON), `DEV_IMPORT_DICTIONARIES` (zips in order); the others fill in from the shared setup. Per app: `DEV_KAVITA_URL/KEY` (Yomu), `DEV_JELLYFIN_URL/USER/PASSWORD` (Miru), `DEV_ABS_URL/KEY` (Yomu, Kiku), `DEV_KAKU_URL/TOKEN`, `DEV_HIDDEN_LIBRARIES` (ids, `|`-separated), `DEV_KECHIMOCHI_URL` (each app's own). `DEV_HOLD_PROGRESS=1` leaves a marker so that simulator never sends reading, watching or listening progress (it stays queued). Hiku's extension: `TEST_RUNNER_UITEST_ENABLE_EXTENSION_ONLY=1 xcodebuild test -scheme Hiku -only-testing:HikuUITests/ExtensionLookupUITests/testEnableExtensionOnly` turns it on in Settings (then uninstall the runner). Manga OCR: copy a `compiled/` models folder into Yomu's `Application Support/OCRModels`.
- Real dictionaries go in the gitignored `Dictionaries/` folder (for example Jitendex, JPDB frequency and Kanjium). Use them with:
  - Package tests: `REAL_DICTIONARY_ZIPS="<zip>|<zip>|…" swift test --filter RealDictionaryTests` in `Packages/Dictionary`
  - Popup renders (macOS): `REAL_DICTIONARY_ZIPS="<zip>|…" POPUP_RENDER_DIR=<folder> swift test --filter RealPopupRenderTests` in `Packages/Lookup` writes the popup for a few sample words as HTML and dark-mode PNGs, to check its layout by eye
  - UI tests: `TEST_RUNNER_UITEST_DICTIONARY_ZIPS="<zip>|…" xcodebuild test … -only-testing:YomuUITests/DictionaryUITests` (without it they use a tiny generated dictionary)
- Mining UI tests (Yomu): `testMiningAWordFromAPage` runs with the OCR env (cards stay queued). To send real cards, add `TEST_RUNNER_UITEST_ANKI_URL` and `TEST_RUNNER_UITEST_ANKI_DECK=<scratch deck>` (create it with `createDeck`; `testCardMinedOfflineIsSentAfterReconnecting` also needs both). Afterwards delete the scratch notes, their `amatsubame_*` media files and the deck. Never point tests at a real deck.
- AnkiConnect compatibility: some AnkiConnect proxies are stricter than AnkiConnect itself, so the apps stick to a safe subset: no extra params; media goes up with `storeMediaFile` before `addNote` (some proxies silently drop `addNote`'s `picture`/`audio`), and media names use only `[a-z0-9_.]` (`AnkiNoteHandler.safeFilename`), since some lowercase file names; nothing relies on `getMediaFilesNames`, `apiReflect` or `guiBrowse`, or on `storeMediaFile`'s return value.
- Word marks: `MinedWordStore` keeps every note of the mining deck (Settings ▸ Cards) with `known` = a card's interval is 21 days or more (`deck:"…" prop:ivl>=21`); queued cards count as learning. `MiningService.refreshMinedWords` runs at launch and every 30 minutes, and `revision` bumps when states change. `WordScanner` (Dictionary) splits text into words on its own hoshidicts lookup (longest deinflected match, starting only at kanji, katakana or a hiragana prefix before kanji; marks words with kanji and katakana words of 2+). Miru: `WordMarkCache` (Lookup) per line, drawn by `TappableLine`. Yomu books: `BookReader.js` `wordRuns`/`markWords` wrap words in `<km-w>` (its own element name, so XPath positions don't move), split per section and cached as `.words-v1-<section>.json` in the book folder. Switch: Settings ▸ Lookup ▸ Mark Words by Anki State (`AnkiSettings.marksWords`).
- Stats tab: `ActivityLog` (Core/Stats.swift) keeps `activitySession` rows in each app's own database: reading adds characters (books, only real page moves, capped at 2,500 a move) or pages (manga, one page or spread forward), Miru adds seconds that played forward (no seeks); a pause over 5 minutes starts a new session. `lookupEvent` counts taps that found results. Cards mined come from the mining deck's note ids (creation times), cached in `statsState`, plus this app's unsent cards; per series from this app's outbox cards (`MinedCard.seriesKey/seriesTitle`, older ones by their MiscInfo title). The shared screen is `StatsView` (AppCommon, Swift Charts); `UITEST_STATS=1` seeds a week of data. Nothing is sent to kechimochi; Settings ▸ Stats holds its URL. Downloads and the cache are in Settings ▸ Storage (`StorageView` in each app).
- Downloads (phase 8): records in the `download` table (`DownloadStore`), shared UI in `AppCommon/DownloadViews.swift`. Miru's episodes go through `EpisodeDownloader` (background URLSession, files in Application Support/Downloads); Yomu's volumes through `VolumeDownloader` (pinned pages in `PageCacheStore`, pinned books in `BookRepository`, both under Application Support/ReaderStorage, not Caches). Nothing downloads unless the user asks, except Yomu's automatic downloads, which the user turns on per library (`AutoDownloadManager` in Yomu/Library/AutoDownloads.swift, rules in `KavitaKit/AutoDownloadPlanner`, settings in `autoDownloadSetting`): a started series (Kavita On Deck or read on this device) keeps the volume being read plus N after it, and finished volumes can be removed (never the open one). A manga volume is done once its pages are in; OCR follows as its own step (`Extra.textPending`). Offline (or Kavita unreachable) the Library shows only series with downloads. Use `path(percentEncoded: false)` for FileManager paths (Application Support has a space).
- Mac: Yomu reads in the main window (`AppEnvironment.readingSession` covers the tabs), and Miru plays there too (`PlayerEnvironment.playingSession`; Escape or Playback → Close Video ⌘[). Menus are `ReaderMenus` and `PlayerMenus` (focused values `readerPaging`, `readerClose`, `playback`).
- Driving the Mac app for live checks: launch with `--args -ApplePersistenceIgnoreState YES` (restored reader windows otherwise catch clicks and turn pages), and restore any reading progress a test changes.
- **Shared screens:**
  - **Cards:** replaced by the one Anki page (below).
  - **Dictionary search:** it takes romaji (`Romaji` in the Dictionary package: hiragana first, then katakana for loanwords), and a typed search counts once in Stats when submitted or left on screen for 1.5 s.
  - **Audio Sources:** URL keys (`apiKey`, `token`…) show masked and are kept in the Keychain, not the database (`Lookup/AudioSourceKeys`). The saved template has `{key:<id>}` in each key's place, and one Keychain item (`audioSource.keys`) holds every source's keys as JSON. It's in the shared group with the AnkiConnect key when the setup is shared, and is copied along when an app joins or leaves. Keys saved in the database by older builds move there at the next launch.
  - **Tabs:** tapping the tab that's showing returns it to its top screen in Yomu, Miru and Kiku.
- **Stats ▸ All immersion**: Stats in Yomu, Miru and Kiku switches between the app's own numbers and kechimochi's (`AllImmersionView`, `ImmersionModel`).
  - **Source:** it reads kechimochi 0.3.3 through `KechimochiKit`, which can only use `/api/version`, `/api/dashboard/snapshot` and `/api/dashboard/heatmap-year`. Those are read-only, though the last two are POSTs. kechimochi has no login, so KechimochiKit must never call `/api/reset`, imports or deletes. The address is the page set in Settings ▸ Stats.
  - **What it shows:**
    - the heatmap: weeks from Sunday, shaded by quarters of the year's days with activity, the busiest always brightest (`ImmersionHeatmap`), with a year menu;
    - the Total, Longest streak and Daily average tiles;
    - time by activity type in each app's color (Listening Kiku, Watching Miru, Reading Yomu, others grey).
  - **Offline:** the last answers are kept (Core `v29_kechimochi_cache`), so it shows them with their age.
  - **Never combined:** kechimochi's totals are never added to the app's own; the footer says so.
- **iPhone Duo** (the foldable): `Fold.swift` in Lookup, `FoldLayout.swift` in AppCommon.
  - **`FoldReader`** (in Lookup, so the readers can use it) gives a view the fold crossing it (`Fold`, also `Fold.crossing(geometry)`, and `onHingeChange`): the crease's frame with its margins, from iOS 27.1's `reservedRegions(kind: .division)`, and the hinge from `onHingeChange`. In the simulator the crease is reported on the inner screen only, 41 pt wide: down the middle in landscape (x 455–496 of 951), across in portrait (y 455–496 of 951). The system marks it inactive while the screen lies fully open; `Fold.isActive` says so, but layouts avoid it either way. The outer screen reports no hinge in the simulator, so Yomu treats a phone that has reported one, with no crease crossing it, as folded.
  - **Side safe areas:** the outer screen's clock and status column (and the tab bar beside it) are a side safe area. Horizontal shelves use `shelfScrollClip()` so they stop there instead of `scrollClipDisabled()` running under it, and manga pages stay out of it.

- **Settings, setup and recommended dictionaries:**
  - **Settings:** every app is built from `SettingsKit` (AppCommon) in one order:
    - `SettingsStatusCard`: a chip per server checked read-only when Settings opens; servers not set up are greyed. It also shows what's waiting to sync (`OutboxStore.waitingCounts`) and startup errors.
    - The app's own section.
    - `LookupAndMiningSection`, whose Anki row opens `AnkiSettingsPage`: the connection, cards and AnkiWeb on one page, with Miru's Card Picture in its extras slot.
    - `StatsSettingsLink`.
    - `SettingsFooterSection`: Storage, Advanced and About.
  - **Advanced** (`AdvancedSettingsView`): Share Setup, Waiting to Sync by kind (`OutboxView(kind:)`, which can clear progress kinds), Run Setup Again, and Troubleshooting with Export Logs.
  - **Logs:** `AppLog` (Core) keeps a rolling `Application Support/Logs/app.log` of server errors, sync, dictionaries and setup, blanking tokens, keys and passwords. Export Logs shares it with the debug logs.
  - **First-launch setup** (`SetupFlow`, `SetupSteps`, AppCommon):
    - **Steps:** each app supplies its server, libraries and extras steps; `SetupProgress` keeps the step per app.
    - **Existing installs:** setup is marked finished once, while it hasn't started and the server is connected. Run Setup Again (`setup.runAgain()`) shows it at once.
    - **Shared setup:** `SharedSetup.origin` (`origin.json`) records which app made it, for "Use your existing setup?". `SharedSetup.members` (`members.json`) records each app's choice when it opens or changes it, so "Shared with …" lists only the apps that share. "Set Up Separately" switches the app to its own setup from the next launch (setup says how to close and reopen it), resuming at Dictionaries.
    - **Tests:** `DevSetup` and the in-memory UI test modes skip setup.
  - **Recommended dictionaries:** `RecommendedDictionaries` is the catalog (Jitendex, JMnedict, KANJIDIC, Jiten global frequency, Kanjium); `DictionaryUpdater` installs it and checks weekly.
    - **Source table:** `dictionarySource` (Core `v31`) records each dictionary's catalog id and its own `index.json` update address. It's part of the shared setup.
    - **Updates:** an update keeps the dictionary's id, order and on/off, installing into a new folder (`DictionaryRecord.folder`) beside the old one; the frequency sort follows the new title. A revision the index names but a download doesn't bring is kept as `undeliveredRevision` and not tried again.
    - **When updates run:** automatic checks run only on Wi-Fi outside Low Data Mode, one app at a time (`.update-lock`). Setup and Add Recommended download on cellular too.
    - **Deleted dictionaries:** deleting a recommended one is remembered (`removedRecommended`).
    - **Hiku:** its own setup is never updated (the extension's built-in dictionaries).
  - **Testing setup:**
    - `UITEST_SETUP_DATA=<name>` gives a launch its own data set: folder, Keychain items, defaults and shared setup. Two apps given the same name share a setup.
    - `SetupUITests` in YomuUITests, MiruUITests and KikuUITests read test accounts on your servers from `.env` (`TEST_*`, `SharedUITests/SetupUITestSupport.swift`) and skip without them. Use dedicated non-admin accounts, not your own. `TEST_KAVITA_LIBRARIES`, `TEST_JELLYFIN_LIBRARIES` and `TEST_ABS_LIBRARIES` name two of each account's libraries as `<Japanese-named library>|<English-named library>` (e.g. `漫画|Books`), to check setup's library guess. Miru's and Kiku's tests need Yomu installed; they make a shared setup with Yomu's DevSetup.
    - `UITEST_STALE_DICTIONARY=<catalog id>` makes an installed one look out of date, for Check Now.
